## Project Overview

This project provides AWS CloudFormation templates for deploying production-ready CloudWatch alarms for Amazon MSK clusters. ## Technical Decisions Made

1. **Per-broker alarms via Lambda custom resource** — CloudFormation can't natively loop over broker IDs, so a Lambda creates alarms using the CloudWatch API with correct dimensions (`Cluster Name` + `Broker ID`)
2. **Cluster-level metrics** (dimension: `Cluster Name` only): `ActiveControllerCount`, `OfflinePartitionsCount`
3. **Broker-level metrics** (dimension: `Cluster Name` + `Broker ID`): `CpuUser`, `CpuSystem`, `HeapMemoryAfterGC`, `KafkaDataLogsDiskUsed`, `UnderReplicatedPartitions`, `UnderMinIsrPartitionCount`, `TrafficShaping`, `BwInAllowanceExceeded`, `BwOutAllowanceExceeded`, `NetworkRxErrors`, `NetworkTxErrors`, `VolumeQueueLength`, `IAMTooManyConnections`
4. **RootDiskUsed alarm removed** — decided not to alarm on this metric
5. **ActiveControllerCount period** — set to 1 minute (60s), not 5 minutes
6. **Lambda function names** — auto-generated by CloudFormation (not hardcoded) to avoid 64-char limit issues
7. **No S3 required for deployment** — users download YAML to CloudShell and use `--template-body file://`
